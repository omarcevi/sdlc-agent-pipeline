# AGENTS.md

Instructions for any coding agent (Claude Code, Gemini CLI, Codex, etc.) working in this repository.

## Project

A multi-agent system built on Google ADK 2.x that turns a GitHub issue into a tested pull request. A graph `Workflow` connects Planner, Coder and Reviewer LLM agents with deterministic function nodes. Code runs in hermetic sandboxes (local Docker or Agent Runtime Sandboxes). The system is measured with a hidden-test benchmark against a single-agent baseline.

- **Design spec (source of truth):** `docs/superpowers/specs/2026-09-29-sdlc-agent-pipeline-design.md`
- **Status:** Core loop and measurement harness implemented (bench mode only, local Docker sandbox): the multi-agent pipeline, the single-agent baseline, the matrix runner and the report. First comparison: `docs/results/2026-09-30-week2a-comparison.md`. Live GitHub mode, the Agent Runtime sandbox backend and the web UI are not built yet.

Read the spec before making architectural changes. If the code and the spec disagree, stop and ask. Do not quietly pick one.

## Hard rules

1. **No AI attribution.** Never add Claude, Claude Code, or any AI tool as author, co-author or contributor. That means no `Co-Authored-By:` trailers, no "Generated with ..." lines in commits, PRs, docs, or a CONTRIBUTORS file. Commits use the repo owner's git identity only. This rule is about work in this repository. The pipeline's own pull requests, comments and commits on the demo repositories name the pipeline (`issue-to-pr`) and its model openly; that is the product's identity, not AI attribution of work in this repository.
2. **The sandbox gets no credentials and no network.** The GitHub token is read only by the orchestrator-side nodes `fetch_issue`, `open_pr` and `report_failure`. Never pass it into prompts, session state, traces, or a sandbox.
3. **Tools go through `Environment`.** Agent tools must never call `subprocess`, `open()` or the host filesystem directly.
4. **Never trust model claims for routing.** Routing uses real `git diff` output and real test exit codes from function nodes.
5. **Benchmark integrity.**
   - Never tune prompts against `split: heldout` tasks, and never open or print their contents during development.
   - Never edit `hidden_tests/` to make a run pass.
   - Run `bench validate` after changing anything under `bench/repos/`.
   - Held-out task directories (`bench/tasks/*-h[0-9][0-9]/`) are sealed: never open, print or diff them, not even as file names in a diff stat. Exclude them from review diffs with the pathspec `':(exclude,glob)bench/tasks/*-h[0-9][0-9]/**'`; a pattern without `/**` does not exclude the files inside.
   - Keep git output quiet around them: `git commit -q`, `git cherry-pick ... >/dev/null`, `git merge --no-stat`. Run pytest with `--tb=no` when held-out tasks are collected. Never review a held-out change in a GitHub PR's file view.
6. **Keep the cost guards.** The budget plugin, sandbox TTLs and loop bounds stay on. Changing their defaults needs the owner's approval.
7. **Don't change model names unless asked.** Models are configured through env vars (`PLANNER_MODEL`, `CODER_MODEL`, `REVIEWER_MODEL`). Bench runs take their models from `--preset`; the three role variables configure `app/agent.py`.
8. **Never deploy, create cloud resources, or push to GitHub without explicit approval** from the owner, given in the current session.

## Runtime wiring

- `app/pipeline.py` builds the graph; `app/agent.py` exposes it to agents-cli as `root_agent` / `app`; `app/driver.py` (`run_pipeline`) is the entry point for bench and live runs and the only place that releases the sandbox of a run it drives.
- Live graph and human approval: `build_workflow(models)` is the bench graph (ends at `deliver_patch`, never pauses; its edges and the baseline's are pinned by tests). `build_workflow(models, live=True)` uses `fetch_live_issue` as `fetch_issue` and adds `deliver_patch → human_gate → route_approval → {approved: open_pr, rejected: report_failure}`. `human_gate` (`app/nodes/gate.py`, `rerun_on_resume=False`) yields `waiting for human approval`, then ADK's `RequestInput` (`interrupt_id` `approve-<run-id>`, payload `app.approval.ApprovalRequest`: branch, title, issue URL and body built with the same `pr_text` calls `open_pr` publishes with, minus the approver footer; files and counts; patch path and hash; test result; review verdict; cost and tool calls), and the run's first pass ends with a pending `adk_request_input` call. The driver then releases the sandbox, asks `run_pipeline(..., approver=...)` (an `Approver`: `ApprovalRequest` → `ApprovalDecision(approved, approver, patch_sha256, note)`) under `APPROVAL_TIMEOUT_S`, and resumes the same session (session state carries `patch_sha256`, `patch_created_at`, `protected_paths`) with one function response holding the decision, under a 300 s cap of its own (expiry: `infra`); the resumed events are appended to the same `events.jsonl`. No approver: `failed` / `infra`, "approval needed but no approver", at once. A timeout is the decision `approved=False`, empty approver, note "approval timed out" (no login, so the failure comment mentions no one). `route_approval` routes `approved` only when `approved` is true and the decision's hash equals state `patch_sha256`, and passes the decision on as its output (which `open_pr` reads); otherwise state `failure` (kind `rejected`: "not approved by <login>[: <note>]", "approval was for a different patch", or the note) and `approver` (read by `report_failure` for its "Decision by" line). `TerminalApprover(login)` shows repository, issue, base and planned branch, test result and verdict, diff stat, the patch (first 400 lines, then its path), title and body, then cost and tool calls, with control characters shown escaped; only the exact word `approve` approves, and the decision carries the hash of the patch file it showed. A `GitHubError` or `GitHubConfigError` from `open_pr` (401, 403, 422, a branch at another commit) ends the run `failed` / `infra`, "GitHub refused the pull request" (no response text); `open_pr`'s own `RuntimeError` guards (not approved, hash differs, unsafe or protected path, `.git` path, patch does not apply, symlink, old git) and an `ArchiveError` there stay crashes: earlier nodes enforce each of them, so reaching one is a harness bug, and the crashed run keeps its record. `RunRecord` gains `pr_url`, `comment_posted` (from the outcome) and `approval_wait_s`; `duration_s` excludes the wait.
- `app/baseline.py` builds the single-agent baseline graph (`build_baseline_workflow`): fetch, provision, one `solo` agent (same tools, sandbox, guardrails and budget as the coder), `route_solo`, diff, tests, deliver, with the same 3-return test-fix loop. It drops only the planner and the reviewer. Both systems run under the same per-run caps (cost, tool calls, wall clock).
- Runner-wide plugins, in order: `BudgetPlugin` (cost and tool-call caps), ADK's `ReflectAndRetryModelPlugin(max_retries=2)` (retries malformed function calls), `GuardrailPlugin` (shell and protected-path checks), `SandboxReleasePlugin` (`app/agent.py` only: at the end of a run, or on its error, it releases the sandbox that run started, because a run under agents-cli has no driver `finally`; the driver does not install it), then the BigQuery analytics plugin when it is enabled. The driver inserts an internal tracker, used for failure classification, right after the budget plugin. The order matters: a plugin that returns a value stops the ones after it.
- The driver bounds the whole event loop with `RUN_TIMEOUT_S` (`asyncio.timeout`); it cancels the in-flight work cooperatively (not a hard kill: a task that swallows cancellation could still block); only the cap's own expiry becomes a `budget` failure, an outer cancellation still propagates. `bench.matrix` waits `INFRA_RETRY_PAUSE_S * k` (30 s default) before infra rerun k.
- Task format (`app/task_store.py`): `task.yaml` also takes `tempting: bool` (default false) and `levers: [...]` (from `LEVERS`: `multi_file`, `distant_symptom`, `doc_rule`, `regression_risk`, `shortcut`). A tempting task ships a `shortcut/` overlay (applied after `plant/`, never together with `solution/`) that must pass the visible tests and fail the hidden ones; `bench.validate` checks this and prints only fixed problem strings. Result rows and the report also carry repo and difficulty breakdowns.
- Delivery (`app/nodes/finish.py`, public text in `app/pr_text.py`): `deliver_patch` writes `patch.diff`, `pr_body.md` (the rendered pull request body) and state `patch_sha256` (SHA-256 of the full diff, UTF-8) and `patch_created_at` (the fixed commit date, so a re-run makes the same commit) in both modes. The source archive is extracted by the same `app/archive.py` as live intake (refused if it holds any `.git` path, a link, a case-folded duplicate name, or too many bytes or files), and host git runs with `safe.bareRepository=explicit` so an archive that looks like a repository is never discovered (delivery needs git 2.38 or newer). In live mode `open_pr` checks the diff hash against the state and the approval, refuses `.github/` and protected paths, applies the patch with host `git apply` to the pinned source archive, and publishes through the Git Data API (blobs, tree on the pinned base tree, commit by `issue-to-pr pipeline`, branch `issue-to-pr/<n>-<run-id>`, pull request); there is no clone and no push. `report_failure` in live mode also posts one marked comment on the issue through `post_failure_comment`; a comment that fails is logged and recorded as `comment_posted: false`, never as a different outcome. Public text: model-written text appears only inside code fences the text cannot close, real data is rendered from fields, the body refers to the issue once and uses no closing keyword, and every pull request body and failure comment ends with a footer naming the pipeline, the run and the models. `budget` state lists the models seen in the run (`models`).
- Scoring (`bench/score.py`) runs inside a sandbox; model-written code never runs on the host.
- Reviewer probes measure the reviewer on prepared patches. A probe is `bench/review_probes/<probe-id>/` (`REVIEW_PROBES_DIR`) holding `probe.yaml` (`task_id`, `kind: bad | good`, `source: shortcut | bench-run | hand-written`, `source_run`, `note`) and `patch.diff` (a `git diff` against base + plant, the form the pipeline produces). Probe ids are opaque (`rp-NN`); the kind lives only in `probe.yaml`, which only `app.review_probe.load_probe` (for the task id) and the harness read. The probe set (12 probes, 6 bad and 6 good, over 8 dev tasks) was chosen by a fixed rule from the Week 2B single-agent runs; `bench/review_probes/SELECTION.md` records the selection and the reading rule for probe results. `app/review_probe.py` builds the probe graph (workflow name `issue_to_pr`, input `ProbeRequest`): load probe, provision, planner, route, apply the patch in the sandbox, the pipeline's own diff and test nodes, reviewer, record verdict (a failing visible test is `probe_invalid`, an infra failure). The coder never runs. `bench/probes.py` stores and validates probes against the visible and hidden tests (dev tasks only; a held-out task id is refused before anything of it is read) and `bench/review_probe.py` runs them through `bench.matrix` (`RunSpec.variant` is the probe id; rows add `probe_id`, `kind`, `verdict`, `must_fix`) and reports the catch rate and the false-alarm rate. A bad probe passes the visible tests and fails the hidden ones; a good probe passes both. No probe changes after a reviewer result is seen.
- Live intake (`app.nodes.intake.fetch_live_issue`, live graph only): `RunRequest` takes `mode="live"`, `repo`, `issue_number`, `base_ref`. Preconditions in order (repository in `LIVE_REPOS`, token loads, issue exists, is not a pull request, is open, author allowed, `agent-ok` last added by an allowed login, no open pipeline pull request), then the base branch is pinned to a commit and its tarball saved to `runs/<run-id>/source.tar.gz` (extracted on the host by `app/archive.py`: gzip or plain tar only, the checksum verified, the decompressed size bounded while reading, at most 5000 files and 50 MB, no links or special files, any `.git` path component refused, case-folded duplicate names refused). A failed precondition raises `RunRefused`; the driver records outcome `refused` (failure kind `none`, cost 0, nothing written to the remote, no comment). The bench graph's `fetch_issue` refuses a live request without reading the token. `RunRecord` gains `mode`, `base_ref`, `base_sha`, `base_tree_sha`; `Outcome` gains `pr_opened`, `rejected`, `refused`.
- Issue text reaches every agent only as the `{issue_text}` block `<issue>\nTitle: ...\n\n...\n</issue>` (`format_issue_text`, which neutralises the opening fragment of any `<issue` or `</issue` in the assembled text, in raw, entity, Unicode-lookalike and invisible-character forms, and caps its length), in the instruction of the planner, coder, reviewer and solo agent. `provision_sandbox` outputs the fixed message `Plan the change for the issue in your instructions.`, so no agent's request holds the raw issue elsewhere, or the run id (a test pins this for the bench, baseline and probe graphs). Benchmark numbers from before this prompt change (Weeks 2A and 2B) are a different prompt version: do not pool them with later ones.
- Tracing (`app/tracing.py`) is opt-in. With `TRACE_TO_CLOUD=1`, `bench.run` exports to Cloud Trace: the driver's root span `issue_to_pr.run` (task, run ID, outcome, cost, tool calls) with ADK's workflow, agent, model-call and tool-call spans under it.
- The pipeline's git directory is `/workspace/.pipeline-git`, outside the worktree. Diffs are taken against the baseline commit recorded in state as `baseline_sha`.
- Gemini agents return structured output through ADK's `set_model_response` tool (`app/models.py` reports `output_schema_and_tools=False`), because native output schema + tools loops on the tool call on gemini-3.8-flash. That tool call counts toward the per-run tool-call cap.
- Environment variables:

| Variable | Default | Purpose |
|---|---|---|
| `PLANNER_MODEL`, `CODER_MODEL`, `REVIEWER_MODEL` | `gemini-3.8-flash` | Model per role (`provider/model` strings go through LiteLLM) |
| `RUN_BUDGET_USD` | `1.00` | Per-run cost cap |
| `MAX_TOOL_CALLS_PER_RUN` | `75` | Per-run tool-call cap |
| `RUN_TIMEOUT_S` | `1500` | Wall-clock cap per run; must stay below `SANDBOX_TTL_S`. On expiry the driver cancels the run, records a `budget` failure and releases the sandbox. Not a positive number: error before the run starts. A live run's wait for the approver and its resumed pass are outside it |
| `APPROVAL_TIMEOUT_S` | `3600` | How long the driver waits for the approver of a live run; expiry rejects ("approval timed out"). Not a positive number: error before the run starts |
| `ENVIRONMENT_BACKEND` | `docker` | Sandbox backend |
| `SANDBOX_IMAGE` | `issue-to-pr-sandbox:dev` | Docker image for the sandbox |
| `SANDBOX_TTL_S` | `1800` | Seconds after which a local sandbox removes itself (self-destruct) |
| `BENCH_TASKS_DIR`, `BENCH_REPOS_DIR` | `bench/tasks`, `bench/repos` | Bench task and repo locations |
| `REVIEW_PROBES_DIR` | `bench/review_probes` | Reviewer probe location |
| `RUNS_DIR` | `runs` | Per-run outputs (`events.jsonl`, `record.json`, `patch.diff`) |
| `TRACE_TO_CLOUD` | unset | `1` exports each local run's spans to Cloud Trace in `GOOGLE_CLOUD_PROJECT` (needs the Cloud Trace API and credentials). Spans include prompt and tool content |
| `GITHUB_TOKEN_FILE` | `~/.config/issue-to-pr/github-token` | File holding the GitHub token, read only by `app/github_client.py` (`load_token`); refused if readable or writable by group or others, if not a regular file, or if it does not hold a plain token. Never `GITHUB_TOKEN`, `GH_TOKEN` or the `gh` CLI's login; the token is never put in the environment |
| `LIVE_REPOS` | unset | Comma-separated `owner/name` the live intake may work on (case-insensitive). Unset or empty: live mode is off, and a live request is refused before any request to the remote service |
| `LIVE_ALLOWED_USERS` | unset | Comma-separated logins (case-insensitive) that may author a live issue and add its `agent-ok` label. Unset or empty: every live issue is refused |

## Workflow

This project follows the `agents-cli` lifecycle: scaffold → build → evaluate → deploy → observe.

- Requires `agents-cli` ≥ 1.7.0. Upgrade with `uv tool upgrade google-agents-cli`, then run `agents-cli update`.
- Use `uv` for everything Python (`uv sync`, `uv run ...`). Never call `pip` directly.
- Before writing agent code, study the reference recipes listed in spec §17 (`google/adk-samples` → `core/python/...`).
- Run `agents-cli infra single-project` **before** the first `agents-cli deploy`.

## Testing conventions

- **pytest checks code correctness:** graph routing (using the scripted fake `BaseLlm`), guardrails, budget math, schemas, and the environment backends. pytest must never assert on real LLM output content.
- **Agent behaviour** is measured by `agents-cli eval run` (quality metrics) and the `bench/` benchmark (the resolve rate).
- Write a failing test before implementing deterministic code.

## Commands

| Task | Command |
|---|---|
| Install deps | `uv sync` |
| Lint | `agents-cli lint` |
| Unit tests | `uv run pytest tests/unit` |
| Quick smoke run (calls a real model) | `agents-cli run '{"task_id": "tc-001", "run_id": "smoke-1"}'` |
| Interactive UI | `agents-cli playground` |
| Quality evals (spends credits) | `agents-cli run --stop-server && agents-cli eval run --dataset tests/eval/datasets/pipeline-dev.json --config tests/eval/eval_config.yaml --concurrency 2`. Runs the real pipeline on five dev tasks; `bench/evalsets.py` builds the dataset (`uv run python -m bench.evalsets --write \| --check`) and the metrics are in `tests/eval/metrics/`. It spends model credits and starts one Docker sandbox per case. `--concurrency` defaults to the number of CPU cores. A reused local server keeps its old configuration, hence `--stop-server` first |
| Deploy (approval required) | `agents-cli deploy` |
| Build sandbox image | `make sandbox-image` |
| Docker-backed tests | `make test-docker` |
| Validate bench tasks | `uv run python -m bench.validate` |
| Run bench (spends credits per run) | `uv run python -m bench.run [--tasks a,b \| --split dev\|heldout] [--system multi\|single] [--preset flash\|pro\|mixed] [--repeats N] [--concurrency N] [--out results] [--quiet] [--confirm-heldout] [--skip-validate]`. Defaults: `--split dev --system multi --preset flash --repeats 1 --concurrency 1`. Runs the matrix (`bench/matrix.py`): one model run per task per repeat, so cost scales with tasks x repeats. Results go to `results/<stamp>-<system>-<preset>.json`. Tasks are validated first (`--skip-validate` bypasses); held-out tasks need `--confirm-heldout`; `single` does not accept `mixed`; infra failures are rerun up to twice; progress is printed live, `--quiet` silences it |
| Run bench with traces in the GCP console | `TRACE_TO_CLOUD=1 uv run python -m bench.run --tasks tc-001` |
| Build a results report | `uv run python -m bench.report results/<file>.json [...] --out docs/results/<name>.md [--title "..."]` |
| Validate reviewer probes (Docker, free) | `uv run python -m bench.probes validate [--probes rp-01,...]` prints `<probe-id>: ok` or the problems |
| Make a bad probe from a task's `shortcut/` | `uv run python -m bench.probes from-overlay --task TASK_ID --id rp-NN` |
| List single-agent runs that could become probes | `uv run python -m bench.probes candidates results/<single>.json [...] [--runs-dir runs]` (run ids and task ids only) |
| Run reviewer probes (spends credits: planner and reviewer per run) | `uv run python -m bench.review_probe [--probes rp-01,...] [--repeats 3] [--preset flash] [--concurrency 1] [--out results] [--report PATH] [--quiet] [--skip-validate]`. Validates first (exit 2 on problems); results go to `results/<stamp>-review-probe-<preset>.json` |
| Build the demo repository locally (no GitHub access) | `uv run python -m bench.demo export --repo REPO --out DIR [--email ADDRESS]` makes a repository at `DIR/REPO`: `main` (the clean repo) and `demo/<task-id>` per dev task (base + `plant/` only, a root commit, your own commit identity, or with `--email` that address as author and committer email, no trailers). Demo repositories are published with the owner's GitHub noreply address (`--email <id>+<login>@users.noreply.github.com`). Pushing it is an owner-approved step |
| Print each demo task's expected tree | `uv run python -m bench.demo trees` prints `<task-id> <tree-sha>` for every dev task; held-out tasks are never listed |
| Check a fetched demo repository | `uv run python -m bench.demo verify --dir DIR/REPO` compares `origin/main` and `origin/demo/<task-id>` with the expected trees (`<branch>: ok` or `mismatch`, exit 1 on a mismatch) |
| Write a demo issue's text | `uv run python -m bench.demo issue --task TASK_ID --repo OWNER/NAME --out DIR` writes `title.txt` and `body.md` verbatim and prints the `gh issue create` command for the owner to run |
| Audit the reviewer on past multi-agent runs (Docker, no credits) | `uv run python -m bench.review_audit results/<multi>.json [...] [--runs-dir runs] --out docs/results/<name>.md` pairs each reviewer verdict in `runs/<id>/events.jsonl` with the diff it reviewed, scores each distinct diff once with the hidden tests (the scorer's visible-then-hidden sandboxes), and reports per task and in total: bad caught, bad approved, good sent back, good approved, rounds, distinct diffs. Only `multi` rows of the `dev` split are opened (others are counted); it never prints patch text, test names or test output. A catch counts the verdict, not its reasons |
| Score a recorded run | `uv run python -m bench.score_run --run-id ID [--task TASK_ID] [--runs-dir runs] [--out results/live]` scores `runs/<id>/record.json` in sandboxes and writes `<out>/<id>.json` (matrix fields plus `mode`, `pr_url`, `approval_wait_s`, `issue_text_differs`). The task comes from `--task` or from a `demo/<task-id>` `base_ref`. Exit 2 for a held-out task, a record whose `base_tree_sha` is not the task's demo tree, an unknown task or a missing record |

The smoke-run prompt must be `RunRequest` JSON (`task_id`, `run_id`). It calls a real model, and a sandbox started this way is not released by the driver: only its TTL (`SANDBOX_TTL_S`) cleans it up.
