# Week 3C CI and CD: run log

What the owner-approved steps of Week 3C did, written as they happened. Times are UTC. No project id or number, no resource names beyond the documented account names, no raw tool output.

## Decisions (owner, 2026-10-02)

Design: `docs/superpowers/specs/2026-10-02-week3c-ci-design.md`. Free checks on every push and pull request; paid runs by manual dispatch only; deploys on `v*` tags behind the owner's approval in a protected `production` environment; Workload Identity Federation with two narrow service accounts, no keys. Controller rulings the owner was told about: `ci-runner` is limited to `paid.yaml` on `main`; bench dispatches get 360 minutes, two workers for `flash`, at most 60 runs (30 for `pro` and `mixed`).

## First CI runs (2026-10-02)

- Merge of `week3c-ci` into `main`; the full suite on the laptop, Docker included, passed (1,972). Pushed.
- First `ci.yaml` run: `lint` and `docker` passed; `unit` had 1 failure. Git 2.50 on the runner started automatic maintenance in the background after a test's commit, and its `maintenance.lock` appeared while the test copied the repository. The same race could hit the pipeline's own host-side git (delivery, demo export, probes), which commits in temporary directories that are then deleted. Fixed for every host git call (`maintenance.auto=false`, `gc.auto=0`), test first (`8276cce`).
- Second run: all green. `lint` under 1 minute, `unit` 1 minute (1,907 tests), `docker` 3 minutes (sandbox image, Docker tests, 20 tasks validated). Cost $0.
