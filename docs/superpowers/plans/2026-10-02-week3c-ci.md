# Week 3C: CI and CD on GitHub Actions — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Status:** Spec approved by the owner on 2026-10-02 (commit `089cd8f`). Execution method: subagent-driven (chosen for Week 3). This plan awaits owner review.

**Goal:** Free checks (lint, unit tests, Docker tests, task validation) on every push and pull request; smoke benchmark, evals and benchmarks by manual dispatch; deploys on `v*` tags after the owner's approval click; all cloud access through Workload Identity Federation with two narrow service accounts.

**Architecture:** Three new workflows replace the scaffold's three: `ci.yaml` (free), `paid.yaml` (dispatch, guarded by `scripts/ci_guard.py` before any credential exists) and `release.yaml` (tag, `production` environment). `deployment/terraform/single-project/cicd.tf` adds the WIF pool, the GitHub provider and the accounts `ci-runner` and `deployer`. `scripts/stage_deploy.py` reads its three Terraform outputs from `ITP_TF_OUTPUTS` in CI.

**Tech Stack:** GitHub Actions (ubuntu-latest), `uv`, Python 3.12, `google-agents-cli==1.7.0`, Terraform 1.16 (google provider 7.x), PyYAML for the workflow tests.

**Spec:** `docs/superpowers/specs/2026-10-02-week3c-ci-design.md` (this plan implements it); parent spec `docs/superpowers/specs/2026-09-29-sdlc-agent-pipeline-design.md` §13, §19; Week 3A design for the Terraform root, project pin and deploy staging.

## Global Constraints

- Python 3.12 via `uv` only (`uv run ...`). Never call `pip`.
- Work on branch `week3c-ci`. Never commit to `main` directly.
- Caps and models unchanged: `RUN_BUDGET_USD=1.00`, `MAX_TOOL_CALLS_PER_RUN=100`, `RUN_TIMEOUT_S=1500`, `MODEL_CALL_TIMEOUT_S=480`, `SANDBOX_TTL_S=1800`; Gemini 3.8 Flash; prompts frozen.
- Repository: `omarcevi/sdlc-agent-pipeline`, numeric id `1401169707`, default branch `main`.
- `agents-cli` in CI is `google-agents-cli==1.7.0`, installed with `uv tool install`.
- Every `uses:` is pinned to a full 40-hex commit SHA with the tag in a trailing comment (`# vX.Y.Z`); re-pin rule: query `refs/tags/<tag>` and `refs/tags/<tag>^{}` with `git ls-remote` and use the peeled commit when present. Reuse `pages.yaml`'s pins for `actions/checkout` and `actions/setup-python`.
- Workflows: top-level `permissions: contents: read`; `id-token: write` only in `paid.yaml`'s `run` job and `release.yaml`'s `deploy` job; `contents: write` only in `release.yaml`'s `release` job; every job has `timeout-minutes`; no `pull_request_target` anywhere.
- CI test steps run pytest with `-q --tb=no -rf` (held-out tasks are collected; CI logs are public).
- No JSON key, no secret other than the existing `REPLAY_REDACT` (used by `pages.yaml` only). WIF values are repository variables, not secrets.
- Held-out seal: `bench/tasks/*-h[0-9][0-9]/` is never opened, printed, diffed, uploaded or run. New code selects held-out tasks by directory name only. Review diffs exclude `':(exclude,glob)bench/tasks/*-h[0-9][0-9]/**'`.
- The project id and number are never written into a committed file (they live in repository variables).
- Commits: plain messages, owner identity only, no `Co-Authored-By` or other AI attribution. Never bypass commit signing.
- Before each commit: `uv run ruff format <files> && uv run ruff check --fix <files>`; `agents-cli lint` passes (write its output to a file and check the exit status); `uv run pytest -q --tb=no -m "not docker"` passes. The controller runs `make test-docker` once at merge.
- `AGENTS.md` and `README.md` are written in Task 5 for all of Tasks 1 to 4 (they run in parallel). Each task's report lists the rows Task 5 must add.

## Review Focus

Five failure modes the spec implies that the per-feature tests would not catch. Each has a test in the task that owns the code.

1. **A held-out task disguised in the dispatch input.** Inputs such as `" tc-h01"`, `"TC-H01"`, `"tc-h01,tc-001"`, `"tc-001,,tc-001"` or a path (`"../bench/tasks/tc-h01"`). Expected: every held-out id, in any case or with whitespace, is refused with the fixed message; malformed ids are refused; duplicates are refused; nothing is normalised into a held-out id. Test in Task 1.
2. **A paid dispatch from a branch other than `main`.** Expected: `ci_guard` refuses `--ref` other than `refs/heads/main` before the run job starts, and the WIF binding for `ci-runner` admits only `refs/heads/main`. Tests in Task 1 (guard) and Task 3 (binding).
3. **`ITP_TF_OUTPUTS` present but broken.** An empty string, `null`, a JSON list, a non-string value, or a missing key. Expected: a clear `UsageError`, never a silent fallback to `terraform output` once the variable is set. Test in Task 2.
4. **A release tag on a commit that is not on `main`.** A `v*` tag can point at any commit. Expected: the deploy job checks that the tagged commit is an ancestor of `origin/main` and fails before WIF login otherwise. Test in Task 4 (the step exists, comes before `auth`, and uses `git merge-base --is-ancestor`).
5. **A free workflow that can reach credentials.** Expected: `ci.yaml` has no `id-token` permission, no `secrets.` reference and no `google-github-actions/auth` step; no workflow uses `pull_request_target`. Test in Task 4.

### Task 1: Dispatch guard

**Files:**
- Create: `scripts/ci_guard.py`, `tests/unit/test_ci_guard.py`

**Interfaces:**
- Produces: `python scripts/ci_guard.py --kind {smoke,eval,bench} --ref REF [--system {multi,single}] [--preset {flash,pro,mixed}] [--tasks IDS] [--repeats N] [--accept-over-25] [--tasks-dir DIR] [--budget-usd X]`. Standard library only (no `app` or `bench` import), so it runs before `uv sync`.
- Exit 0: allowed. It prints `worst case: $<cost> for <runs> runs` (cost with two decimals) and, when `GITHUB_OUTPUT` is set, appends `tasks=<comma-separated ids>`, `system=<system>`, `preset=<preset>`, `repeats=<n>`, `runs=<n>` lines to that file.
- Exit 2: refused, with exactly one line on stderr starting `error: ` and nothing on stdout.

**Required behaviour**

1. `--ref` must be exactly `refs/heads/main`, else `error: paid runs start from main only`.
2. `--kind smoke` means tasks `tc-001,tc-003,sr-001`, system `multi`, preset `flash`, repeats 1; it rejects `--tasks`, `--system`, `--preset` and `--repeats` with `error: smoke takes no task, system, preset or repeats`.
3. `--kind eval` means 5 runs (the five cases of `make eval`); it rejects the same flags with `error: eval takes no task, system, preset or repeats`.
4. `--kind bench`: `--system` default `multi`; `--preset` default `flash`; `single` with `mixed` refused with `error: single does not accept mixed`; `--repeats` default 1, integer 1 to 5, else `error: repeats must be 1 to 5`.
5. `--tasks` (bench only): split on commas; each id stripped of surrounding whitespace; an empty item, or an id not matching `^[a-z]{2}-\d{3}$`, gives `error: bad task id`; a duplicate gives `error: task listed twice`; an id matching `-h\d\d` in any case, before or after stripping, gives `error: held-out tasks never run in CI` (checked first, on the raw input, case-insensitively); an id with no directory `<tasks-dir>/<id>` gives `error: unknown task`. Empty `--tasks` means every dev task: the directory names under `--tasks-dir` (default `bench/tasks`) that match `^[a-z]{2}-\d{3}$`, sorted. Held-out directories are excluded by name and never opened; no file inside any task directory is read.
6. Worst case = runs × `--budget-usd` (default `1.00`), runs = tasks × repeats (smoke 3, eval 5). Above $25.00 without `--accept-over-25`: `error: worst case $<cost> is over $25; pass accept_over_25 to run it`.

**Tests** (`tests/unit/test_ci_guard.py`, the script run with `subprocess` against a temporary tasks directory holding dev and held-out directory names):

- `test_main_only`, `test_smoke_is_fixed_and_three_runs`, `test_eval_is_five_runs`, `test_smoke_and_eval_reject_bench_flags`
- `test_bench_defaults_and_whole_dev_split` (held-out directories not counted, not opened: make one unreadable, `chmod 000`)
- `test_held_out_ids_are_refused_in_any_form` (Review Focus 1: `" tc-h01"`, `"TC-H01"`, `"tc-h01,tc-001"`, `"tc-001, tc-h01 "`)
- `test_bad_and_duplicate_and_unknown_ids` (including `"tc-001,,tc-002"`, `"../bench/tasks/tc-h01"`, `"tc-001,tc-001"`, `"zz-999"`)
- `test_single_with_mixed_and_repeats_range`
- `test_over_25_needs_accept` (16 tasks × 2 repeats refused; with the flag allowed)
- `test_github_output_lines` (the file gets exactly the listed keys; stdout holds only the worst-case line)
- `test_refusal_prints_one_error_line_and_exits_2`

- [ ] **Step 2:** Implement; GREEN.

**`paid.yaml`** (`name: Paid run`): trigger `workflow_dispatch` only, inputs `kind` (choice smoke/eval/bench, default smoke), `system` (choice multi/single, default multi), `preset` (choice flash/pro/mixed, default flash), `tasks` (string, default empty), `repeats` (string, default "1"), `accept_over_25` (boolean, default false); `concurrency: {group: paid, cancel-in-progress: false}`; jobs:
